# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Docusaurus 3.7 (React 19, Node >= 18) documentation site for the WPI Humanoid Robot ("Koalby") MQP. It's deployed on Netlify at https://verdant-moxie-980963.netlify.app/. Most changes are Markdown content edits in `docs/`, not code.

## Commands

```bash
npm install          # install dependencies
npm start            # dev server with hot reload at http://localhost:3000
npm run build        # production build into /build
npm run serve        # serve the production build locally
npm run clear        # clear the .docusaurus cache (try this first when a build fails strangely)
```

The repo has no tests and no linter. `npm run build` is the only check. `onBrokenLinks` and `onBrokenMarkdownLinks` are set to `warn`, so broken links don't fail the build. Read the build output for warnings after editing links. Restart the dev server after changing `docusaurus.config.js`.

## Architecture

- **Docs are served at the site root.** `routeBasePath: '/'` in `docusaurus.config.js` means `docs/vision/index.md` is served at `/vision`, not `/docs/vision`. `src/pages/index.js` is the landing page.
- **The sidebar is autogenerated** from the `docs/` folder tree (`sidebars.js` has a single `autogenerated` entry). Order and labels come from:
  - `_category_.json` in each section folder (`label`, `position`, `link` — usually `generated-index` with a description)
  - frontmatter in each page (`id`, `title`, `sidebar_label`, `sidebar_position`)
- **Each top-level section** (`documentation-tutorial`, `python-dev-guide`, `speech-recognition`, `vision`, `locomotion`, `tools`) is also hard-coded in two places in `docusaurus.config.js`: the navbar "Sections" dropdown and the footer "Documentation" links. When you add, rename, or remove a section, update both.
- **Decap CMS** lives in `static/admin/` (`config.yml`, `index.html`) and is served at `/admin`. It commits directly to `main` of `KoalbyMQP/Documentation` through the GitHub backend. Its `sections` collection writes `docs/<label>/_category_.json`, and its `pages` collection writes Markdown with frontmatter. If you change the frontmatter or category conventions, keep `config.yml` in sync. CMS media uploads go to `static/img`. Site assets such as the logo and videos are in `static/assets`.
- **Algolia DocSearch** credentials are read from the env vars `ALGOLIA_APP_ID`, `ALGOLIA_SEARCH_API_KEY`, and `ALGOLIA_INDEX_NAME`. The `algolia` block is only added to the config when `ALGOLIA_APP_ID` is set, because empty values fail Docusaurus config validation. Without the env vars, the site builds with no search.
- **`archive/`** holds old, unrelated projects (the old Humanoid website and a demo repo). They aren't part of the Docusaurus build. Don't modify them unless asked.

## Content conventions

- Every page needs frontmatter with `id`, `title`, `sidebar_label`, and `sidebar_position`. Section landing pages are `index.md` inside the section folder.
- Links between pages use relative `.md` paths (for example `./markdown/index.md`) or root paths that match the `routeBasePath: '/'` scheme (for example `/vision`; a section's `index.md` is served at the folder path, so `/vision/index` is a broken link).
- Admonitions use Docusaurus syntax (`:::note Title ... :::`).
